# るいとの成長日記 (Ruito Growth Diary)

A private, mobile-first **PWA** that collects a child's fleeting voices and expressions as a time capsule. World: *Tamagotchi × soft photo album*. Built to [`ruito_app_mock.html`](ruito_app_mock.html).

## Stack
- **Next.js 14 (App Router) + TypeScript**, PWA (manifest / installable / offline shell)
- **Supabase** — Postgres (metadata) + Storage (audio/images, private + signed URLs)
- **ffmpeg.wasm** — extracts audio from an uploaded mp4 entirely in-browser (single-thread core → no cross-origin-isolation headers needed)
- **wavesurfer.js v7** (regions plugin) — waveform display + trim
- Hosting target: **Vercel** free tier

## Run locally
```bash
npm install
npm run dev      # http://localhost:3000
```
Runs on in-memory mock data out of the box. To persist, connect Supabase — see [`supabase/README.md`](supabase/README.md).

## Screens (bottom tabs)
- **ホーム** — pixel sprite (tamagotchi: idle/happy/cry/sleep/poop, poke to care), profile stats, random memory card + shuffle, tap to play voice.
- **のこす** — 3 steps: mp4 upload → ffmpeg extract → wavesurfer trim → attach photo + route to a じてん category → save.
- **じてん** — きもち (6-level scale) / ことば / なまえ / フリー (custom collections).
- **プロフ** — edit name / birthday / height / weight; birthday drives 生後◯日 and the sprite growth stage.

## Architecture notes
- `lib/store.tsx` — app state; seeds deterministic mock data, hydrates from / persists to Supabase when `lib/supabase.ts` detects env vars (`backed`). Mock fallback otherwise.
- `lib/data.ts` — async CRUD + media upload + signed-URL helpers.
- `lib/sprite.ts` / `lib/age.ts` — pixel-map sprite (5 growth stages) and age math.
- `lib/ffmpeg.ts` — singleton ffmpeg loader, `extractAudio` / `trimAudio`.
- `components/Waveform.tsx` — wavesurfer + regions trimming.
- Icons generated by `scripts/gen-icons.mjs` (dependency-free PNG encoder).

## Privacy
No-login family deployment: privacy relies on keeping the deployed URL private; media is in private buckets via signed URLs. Auth (e.g. magic-link) can be added later — schema and data layer are structured for it. See `supabase/README.md`.
